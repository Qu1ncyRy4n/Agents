## Code Findings

### High: Fenced Markdown Is Parsed As Module Structure

[`library/library.go:244-297`](../library/library.go) recognizes every line
beginning with `#` as a heading. It does not track Markdown backtick or tilde
fences. A code example such as `# Example` inside a fenced block therefore
becomes a selectable node. Rendering can then corrupt the example and expose a
synthetic source path.

Add fence tracking to `parseFile`, and test source indexing plus rendering of
backtick and tilde fenced headings.

### High: Build Is Not Transactional Across Output And State

[`internal/cli/workspace_commands.go:159-163`](../internal/cli/workspace_commands.go)
writes the generated output before writing `.mogent/state.json`. If state
writing fails, `mogent build` reports failure after it has already replaced the
output. The state is then absent or stale, so a later build may refuse to
continue or misclassify the file.

Make CLI build use the same rollback discipline as initialization and session
save. Add failure-injection tests for an unwritable or malformed `.mogent`
state location, including `--force`.

### Medium: State Does Not Identify Its Output Path

[`state/state.go:15-54`](../state/state.go) records only an output hash. One
state file therefore applies to every `output:` value in a manifest. Changing
the output path can treat an unrelated file with matching bytes as generated
and overwrite it without `--force`.

Store the normalized output path with the hash. Treat a path mismatch as an
untracked output that needs explicit force.

### Medium: Atomic Writes Relax Existing Permissions

[`renderfs/write.go:37`](../renderfs/write.go) forces every replacement to mode
`0644`. Rewriting a private manifest, provenance record, or state file changes
it to group/world readable.

Preserve the existing destination mode. Choose explicit restrictive defaults
for new private state/provenance files. Add a restrictive-mode preservation test.

### Low: Source Add Accepts Inputs Later Operations Reject

[`workspace/source_add.go:38-95`](../workspace/source_add.go) accepts aliases
and HTTP(S) URLs that the later remote-pin path rejects. In particular, it can
write a credential-bearing URL into a manifest before source pinning refuses it.

Use the same safe-alias and remote-URL validation before source declaration is
written. Test that invalid input leaves the manifest unchanged.

`Agents/libraries/` was correctly relocated to QMR and removed from this
repository. The following current product material still presents it as an
available live library:

- [`README.md:60-62`](../README.md) and [`README.md:117-120`](../README.md)

source example rather than implying it is bundled with Mogent.

## Library Boundaries

```text
Agents/
  Mogent product code, renderer contracts, CLI, test fixtures, and product docs.
  It does not own a selectable policy library.

qmr-agents-library/
  Personal live modules, personal overlays, templates, design workbench, and
  immutable archive/reference evidence.

cdint-agents-library/ (future independent repository)
  Explicitly reviewed CDINT-owned modules and organization templates.
  It is not a GitHub fork of the personal library.
```

QMR's archive and reference trees are evidence only. Promotion must occur by
copying a bounded candidate into live QMR content, recording its source and
disposition, and dogfooding it. Templates should select only live modules;
archive-rendering is a separately named verification fixture, never a default.

QMR currently has a live core-and-constraints template under
`templates/core-and-constraints/`. Its README still names the removed
`all-archived-content` template and says live extraction is future work. Update
that README in the same change that commits the new live modules and template.
