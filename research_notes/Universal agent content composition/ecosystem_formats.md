# Established agent content formats for a universal `.agents` composer

Research snapshot: 2026-10-09. Evidence means **documented support by a tool**, not measured popularity, installation counts, or runtime conformance testing. Sources below were fetched directly from primary specification/vendor documentation. Scope decision supplied by the user: **whole-file opaque import only**; semantic TOML/YAML/JSON composition is deferred. Preserving YAML frontmatter inside an imported Markdown file is within scope.

## 1. Which formats and paths have documented tool support?

### Takeaway

Agent Skills is a shared **bundle format**, while `.agents/skills` is a documented discovery convention supported by Codex, OpenCode, Copilot, and Cursor. Instruction files, rules, custom agents, commands, and settings retain tool-specific paths and behavior; the specification does not turn every vendor directory into a universal `.agents` namespace. [Specification](https://agentskills.io/specification), [Codex skills](https://developers.openai.com/codex/skills), [OpenCode skills](https://opencode.ai/docs/skills/), [Copilot skills](https://docs.github.com/en/copilot/concepts/agents/about-agent-skills), [Cursor skills](https://cursor.com/docs/context/skills)

### Cited Findings

#### Shared conventions and namespace boundaries

| Content | Verified format/convention | Evidence and boundary |
| --- | --- | --- |
| Agent Skills | A directory containing exact `SKILL.md`, with YAML frontmatter and Markdown body; optional resources and arbitrary additional files/directories | The specification defines the skill directory's contents, not a mandatory host-wide `.agents` root. [Specification](https://agentskills.io/specification) |
| `.agents/skills/<name>/SKILL.md` | Repository discovery path; `~/.agents/skills/<name>/SKILL.md` is a personal path | Explicitly supported by Codex, OpenCode, Copilot, and Cursor. This is concrete interoperability evidence. [Codex](https://developers.openai.com/codex/skills), [OpenCode](https://opencode.ai/docs/skills/), [Copilot](https://docs.github.com/en/copilot/concepts/agents/about-agent-skills), [Cursor](https://cursor.com/docs/context/skills) |
| `AGENTS.md` | Plain Markdown instruction file in a repository root and/or nested directories | Documented by Codex, OpenCode, Copilot, and Cursor, with differing discovery semantics. Current Claude Code also documents conditional direct support. It is a filename, not the `.agents` directory or a custom-agent definition. [Codex](https://developers.openai.com/codex/guides/agents-md), [OpenCode](https://opencode.ai/docs/rules/), [Copilot](https://docs.github.com/en/copilot/how-tos/configure-custom-instructions/add-repository-instructions), [Cursor](https://cursor.com/docs/context/rules), [Claude](https://code.claude.com/docs/en/memory#agents-md) |
| `.claude`, `.github`, `.opencode`, `.cursor` | Vendor/host-specific directories with several content types | Compatibility with particular paths does not make the entire directory layout an Agent Skills standard. The cited vendor pages define their respective conventions. [Claude](https://code.claude.com/docs/en/skills), [Copilot](https://docs.github.com/en/copilot/concepts/agents/about-agent-skills), [OpenCode](https://opencode.ai/docs/config/), [Cursor](https://cursor.com/docs/context/rules) |

**Naming distinction:** `.agent` (singular directory), `.agents` (plural directory), `.agents.md` (file), `AGENTS.md` (file), and `*.agent.md` (agent-profile suffix) must be represented separately. No fetched source establishes `.agent` as an alias for `.agents`. Codex shows `.agents.md` only as an explicitly configured fallback instruction filename; Copilot uses `.agent.md` for profiles. [Codex instruction discovery](https://developers.openai.com/codex/guides/agents-md#customize-fallback-filenames), [Copilot agent creation](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/create-custom-agents)

### Inferences

- A composer can use `.agents` as its own canonical storage root, but it needs explicit target-path adapters. Only `.agents/skills` discovery is established here across several tools; arbitrary `.agents/rules`, `.agents/agents`, `.agents/hooks`, or `.agents/settings.*` cannot be labeled supported universal locations from these sources. [Skill specification](https://agentskills.io/specification), [Codex paths](https://developers.openai.com/codex/skills), [OpenCode paths](https://opencode.ai/docs/skills/), [Copilot paths](https://docs.github.com/en/copilot/concepts/agents/about-agent-skills), [Cursor paths](https://cursor.com/docs/context/skills)
- Instruction **content** portability is stronger than scope/precedence portability: Codex's override chain, Claude's accumulated/lazy instructions, Copilot's nearest AGENTS, and OpenCode's documented first-match categories differ. Import records should retain tool, scope, original path, and intended output path. [Codex](https://developers.openai.com/codex/guides/agents-md), [Claude](https://code.claude.com/docs/en/memory), [Copilot](https://docs.github.com/en/copilot/how-tos/configure-custom-instructions/add-repository-instructions), [OpenCode](https://opencode.ai/docs/rules/)

### Gaps

- No popularity ranking, usage share, or installation-count evidence was collected. “Supported by tool” is the entire adoption claim.
- No fetched source verifies `.agent` as a universal root; no automatic singular/plural alias should be inferred.
- Claude skill docs establish `.claude/skills`; this review did not establish direct Claude Code skill discovery from `.agents/skills`. Claude's statement about ignoring `.agents/` in AGENTS instruction discovery concerns **instructions**, not a comprehensive skills test.
- Copilot CLI-only personal custom-agent/instruction paths and all IDE-specific discovery overrides were not exhaustively researched. Do not extrapolate repository/cloud paths to them.
- These are documentation-supported paths, not a compatibility test against installed releases. Current docs contain version-specific additions and preview/deprecation states.

## 2. What must opaque imports preserve, especially Markdown frontmatter and bundles?

### Takeaway

The import unit should be an intact file for individual instructions/rules/profiles/configuration and an intact directory tree for a skill. YAML frontmatter is operational metadata embedded in Markdown; preserving it is distinct from implementing semantic YAML composition. [Skill specification](https://agentskills.io/specification), [Claude frontmatter](https://code.claude.com/docs/en/skills#frontmatter-reference), [Cursor rules](https://cursor.com/docs/context/rules), [Copilot profiles](https://docs.github.com/en/copilot/reference/custom-agents-configuration)

### Cited Findings

#### Skill contract and frontmatter sensitivity

- The specification requires opening YAML frontmatter plus Markdown body, `name` (1–64 characters) and `description` (1–1024 characters). Name must match the immediate parent directory, use lowercase alphanumerics/hyphens, and avoid leading/trailing/consecutive hyphens. Optional standard fields are `license`, `compatibility` (up to 500 characters), string-to-string `metadata`, and experimental `allowed-tools`. [Specification](https://agentskills.io/specification)
- Specification wording describes both “unicode lowercase alphanumeric” and examples/constraints using `a-z`/`0-9`; OpenCode supplies an explicit ASCII regex `^[a-z0-9]+(-[a-z0-9]+)*$`. An ASCII-safe generated name is a conservative interoperability choice; opaque import should preserve originals and surface validation separately rather than silently rename. [Specification](https://agentskills.io/specification#name-field), [OpenCode name validation](https://opencode.ai/docs/skills/#validate-names)
- Claude Code is more permissive than the shared minimum: all skill fields optional locally, with description recommended and name defaulting to folder; unknown fields ignored. Frontmatter is recognized **only if opening `---` is the first line**. Malformed YAML can leave a skill loaded with no fields. Local agent definitions with malformed/missing required frontmatter instead get skipped. [Claude skills](https://code.claude.com/docs/en/skills#frontmatter-reference), [Claude agent skips](https://code.claude.com/docs/en/sub-agents#subagent-files-claude-code-skips)
- Claude rules read only `paths`; bad YAML can cause the rule to load unconditionally. Copilot uses `applyTo` and `excludeAgent`; Cursor rules use `description`, `globs`, `alwaysApply`. These keys are not equivalent schemas despite all appearing in Markdown frontmatter. [Claude rules](https://code.claude.com/docs/en/memory#rules-frontmatter-reference), [Copilot instructions](https://docs.github.com/en/copilot/how-tos/configure-custom-instructions/add-repository-instructions#creating-path-specific-custom-instructions), [Cursor rules](https://cursor.com/docs/context/rules#rule-anatomy)
- Claude skill extensions such as `disable-model-invocation`, `user-invocable`, `context`, `agent`, `model`, `hooks`, and `paths` affect behavior. Claude Code accepts them locally, but claude.ai uploads/API/package validation allow only the six standard fields and can **reject** unsupported keys. OpenCode instead ignores unknown skill fields and does not list `allowed-tools` among recognized fields. Shared bundle shape therefore does not guarantee shared frontmatter behavior. [Claude portability](https://code.claude.com/docs/en/skills#using-skill-frontmatter-outside-claude-code), [OpenCode frontmatter](https://opencode.ai/docs/skills/#write-frontmatter)
- Copilot documents `allowed-tools` for skill tool pre-approval. Tool names and permission effects should not be normalized across hosts simply because the field spelling matches. [Copilot skill scripts](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/add-skills#enabling-a-skill-to-run-a-script), [Specification experimental field](https://agentskills.io/specification#allowed-tools-field)

#### Bundling and references

- `scripts/`, `references/`, `assets/` are recommended optional directories, not a whitelist. A skill can contain other files and directories. Metadata, full instructions, and resources are progressively loaded; the specification recommends relative references from the skill root. Importing only `SKILL.md` can omit actual workflow dependencies. [Specification](https://agentskills.io/specification#optional-directories)
- Preserve `<skill>/agents/openai.yaml` and its referenced assets/dependencies as part of a Codex skill bundle; it is a host-specific YAML sidecar and remains an opaque file under the requested scope. [Codex optional metadata](https://developers.openai.com/codex/skills#optional-metadata)
- Scripts can live directly in the skill root, not only in `scripts/`: Copilot's official example bundles `convert-svg-to-png.sh` beside `SKILL.md`. [Copilot script example](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/add-skills#enabling-a-skill-to-run-a-script)
- References have host-specific semantics: Claude instruction `@path` imports expand automatically; OpenCode AGENTS references do not; OpenCode command `@file` references include file content; Cursor rule references guide agent tool reads rather than automatic inlining. Keep body syntax and location intact rather than treating all `@` expressions alike. [Claude imports](https://code.claude.com/docs/en/memory#import-additional-files), [OpenCode rule references](https://opencode.ai/docs/rules/#referencing-external-files), [OpenCode command references](https://opencode.ai/docs/commands/#file-references), [Cursor rule references](https://cursor.com/docs/context/rules#referencing-files-from-a-rule)
- Claude and OpenCode skills/commands can include shell injection syntax and argument substitution, and VS Code prompt files use file/tool references and input placeholders. These are part of the source dialect, not generic Markdown decoration. [Claude skills](https://code.claude.com/docs/en/skills), [OpenCode commands](https://opencode.ai/docs/commands/#prompt-config), [VS Code prompts](https://code.visualstudio.com/docs/copilot/customization/prompt-files#_prompt-file-format)

#### Standalone structured configuration

| Payload | Import treatment under the requested scope | Evidence |
| --- | --- | --- |
| Claude `settings.json`, `settings.local.json`, plugin `hooks/hooks.json` | Whole file only; preserve strict JSON. Keep referenced hook scripts as associated dependencies. Do not extract/merge hooks, permissions, or plugin keys. | [Settings](https://code.claude.com/docs/en/settings), [Hooks](https://code.claude.com/docs/en/hooks#hook-locations) |
| OpenCode `opencode.json`, `opencode.jsonc` | Whole file only, preserving comments and substitutions where present. Native OpenCode merges its own config sources; composer need not reproduce that. | [Config](https://opencode.ai/docs/config/) |
| Codex `config.toml`, skill `agents/openai.yaml` | Whole file only; no TOML table or YAML mapping composition. Sidecar remains inside its bundle. | [Codex skills/config](https://developers.openai.com/codex/skills) |
| YAML frontmatter in `.md`, `.mdc`, `.agent.md`, `.instructions.md`, `.prompt.md` | Preserve in the intact Markdown file, including delimiters and original field spellings. No standalone semantic YAML merger is required. | [Specification](https://agentskills.io/specification), [Cursor](https://cursor.com/docs/context/rules), [Copilot](https://docs.github.com/en/copilot/reference/custom-agents-configuration), [VS Code](https://code.visualstudio.com/docs/copilot/customization/prompt-files) |

### Inferences

- **Recommended opaque import contract:** copy whole file bytes, or recursively copy a skill directory with relative paths and executable permissions intact. Retain source tool/scope/path outside payloads. This follows from first-line frontmatter parsing, name-directory coupling, relative references, executable scripts, and sidecars. [Claude parsing](https://code.claude.com/docs/en/skills#frontmatter-reference), [Specification](https://agentskills.io/specification), [Claude hook executable example](https://code.claude.com/docs/en/hooks#how-a-hook-resolves), [Codex sidecar](https://developers.openai.com/codex/skills#optional-metadata)
- Do not prepend provenance banners to frontmatter-bearing imports, concatenate multiple profile files into one, strip frontmatter, rename a skill directory independently of `name`, or flatten supporting resources. These changes can alter discovery, scope, identity, and reference resolution. [Claude first-line parsing](https://code.claude.com/docs/en/skills#frontmatter-reference), [Skill naming/references](https://agentskills.io/specification), [OpenCode filename identity](https://opencode.ai/docs/agents/), [Cursor rules](https://cursor.com/docs/context/rules)
- Same-destination conflicts should be represented as selection/replacement of an entire opaque file or bundle, not invented field merging. Native tool precedence can be documented without being reimplemented by the composer. [Codex same-name skills](https://developers.openai.com/codex/skills), [Claude profile precedence](https://code.claude.com/docs/en/sub-agents#choose-the-subagent-scope), [OpenCode native config merge](https://opencode.ai/docs/config/)
- Host-specific Markdown should initially be classified/imported in its own dialect. A Claude subagent file, Copilot agent profile, and OpenCode agent file all contain YAML+Markdown but differ in identity, model syntax, tool names, permissions, and schema; a generic file copy is not a semantic converter. [Claude agents](https://code.claude.com/docs/en/sub-agents), [Copilot agents](https://docs.github.com/en/copilot/reference/custom-agents-configuration), [OpenCode agents](https://opencode.ai/docs/agents/)

### Gaps

- Runtime execution, dependency installation, validation against all host versions, and conversion of embedded tool names are outside this inventory and were not tested.
- Symlinks need an explicit import policy: Codex/Claude document support, but cross-platform copying/export and target-host link handling were not comprehensively verified. No automatic dereference policy is implied. [Codex skills](https://developers.openai.com/codex/skills), [Claude skills](https://code.claude.com/docs/en/skills#where-skills-live)
- Whole-file preservation cannot by itself repair external absolute paths or references to files outside an imported bundle; required relocation behavior remains a composer design question.

## 3. Which import priorities are worthwhile given verified support and deferred semantic composition?

### Takeaway

Prioritize intact skill bundles and instruction Markdown, then vendor-native frontmatter-bearing rules/profiles/commands. Structured settings and hook registrations remain worthwhile **opaque payloads**, with lower integration benefit until semantic composition is intentionally designed; these priorities are product recommendations, not popularity rankings.

### Cited Findings

### Inferences

- The first useful composer can be **format-aware for discovery and routing, opaque for content**: recognize established roots, suffixes, bundle boundaries and scopes, while preserving payloads. This supplies import value without requiring semantic TOML/YAML/JSON composition. [Skill boundaries](https://agentskills.io/specification), [Vendor paths](https://opencode.ai/docs/config/), [Copilot suffixes](https://docs.github.com/en/copilot/how-tos/configure-custom-instructions/add-repository-instructions), [Cursor suffix](https://cursor.com/docs/context/rules)
- Put multi-tool `.agents/skills` discovery and full-bundle copying ahead of a generic “merge all Markdown” feature. Operational metadata and resources matter more than the file extension alone. [Specification](https://agentskills.io/specification), [Claude parsing](https://code.claude.com/docs/en/skills#frontmatter-reference), [Cursor rules](https://cursor.com/docs/context/rules)
- Preserve personal/repository/managed/plugin scopes as metadata rather than collapsing them. Local-home assets are not uniformly available in cloud agents; host-specific sync/distribution remains separate from file import. [Claude cloud skills](https://code.claude.com/docs/en/skills#skills-in-cowork-and-cloud-sessions), [Cursor cloud sync](https://cursor.com/docs/context/skills#use-personal-skills-with-cloud-agents), [Codex scopes](https://developers.openai.com/codex/skills)
- Keep precedence and lifecycle qualifications visible in the inventory: Claude direct AGENTS support is version/setting-dependent; VS Code prompt support is transitioning; OpenCode singular folders are compatibility input. This is more actionable than unsupported “most popular format” ordering. [Claude AGENTS](https://code.claude.com/docs/en/memory#agents-md), [VS Code prompts](https://code.visualstudio.com/docs/copilot/customization/prompt-files), [OpenCode directory naming](https://opencode.ai/docs/config/#precedence-order)

### Gaps

- Priority levels above are reasoned recommendations based on interoperability and import feasibility, not measured user demand. Repository scans or customer requirements would be needed to rank expected import volume.
- A universal `.agents` composer still needs its own storage/export manifest and collision policy. No cited standard establishes a universal configuration, rules, hook, command, or custom-agent schema for that directory.
- Additional formats such as plugins, MCP manifests, output styles, and Cursor subagents/hooks were not exhaustively inventoried. A skill's arbitrary bundled files should nevertheless remain intact during opaque import.
