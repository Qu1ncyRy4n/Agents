# Agents Standard and .agents scopes — evidence as of 2026-10-09

## 1. What is normative, what is proposed, and which names/types are specified?

### Takeaway

`agentsstandard.com` publishes nbiish's **Agents Standard**, an independently maintained proposed interoperability/loading protocol with its own specification and CLI. Do not equate its requirements with the separately stewarded AGENTS.md format, the Agent Skills format specification, or verified adoption by every agent. `.agents/skills/` is documented cross-client practice; the whole `.agents/` instruction/MCP/provider cascade is a materially stronger proposal. [Site](https://agentsstandard.com/); [spec repository](https://github.com/nbiish/agents-standard); [AGENTS.md](https://agents.md/); [Agent Skills integration guide](https://agentskills.io/integrate-skills).

### Cited Findings

#### Evidence labels, dates, and reproducibility

- **N-AS** below means prescriptive/normative text **within nbiish's proposed Agents Standard**, not an ecosystem-wide mandate. **N-FORMAT** means requirements in the separate AGENTS.md/Agent Skills format. **GUIDANCE** means integration recommendations. **IMPL** means behavior directly visible in fetched source. **DOC-IMPL** means official product documentation, without execution testing. **CLAIM** means an adoption assertion by Agents Standard that has not independently been verified. These distinctions are necessary because the site says it “proposes” universal paths, while the skills guide says the format “does not mandate where skill directories live.” [Site, MCP problem section](https://agentsstandard.com/#mcp); [Skills guide](https://agentskills.io/integrate-skills).
- All URLs cited here were retrieved via webfetch **2026-10-09**. Undated web pages are retrieval-date evidence, not proof of their original publication date. Both nbiish repositories' fetched `main` heads predate the requested cutoff: specification/CLI **`63e166a76acb61e6a197e2049ba1e87bea0ddf1a`, 2026-05-31T02:51:37Z**; website **`bb838b1853513bed0b6b5a897b407d3324737c00`, 2026-05-31T02:51:06Z**. Their commit messages describe “unified loading protocol — 4 resource types, 5 phases, 67 tests.” The test count is the maintainer's commit claim, not a test run performed for this research. [Spec commit/API](https://api.github.com/repos/nbiish/agents-standard/commits/main); [site commit/API](https://api.github.com/repos/nbiish/agentsstandard-dot-com/commits/main).
- **Version skew is verified:** live `https://agentsstandard.com/agents.json` says **`"version": "1.4.0"`**, `loading_model: scoped-concatenation`, and project `mcp-settings.json`; pinned website-repository `agents.json` says **`"version": "2.0.0"`**, `loading_model: unified-cascade`, and root `.mcp.json`. The spec repository's pinned `llms.txt` says version 2.0.0 and its changelog says **“v2.0.0 (May 30, 2026)”**. Report live-site text, repository text, and code separately; do not silently synthesize them into one consistent latest standard. [Live JSON](https://agentsstandard.com/agents.json); [pinned site JSON](https://raw.githubusercontent.com/nbiish/agentsstandard-dot-com/bb838b1853513bed0b6b5a897b407d3324737c00/agents.json); [pinned spec](https://raw.githubusercontent.com/nbiish/agents-standard/63e166a76acb61e6a197e2049ba1e87bea0ddf1a/llms.txt).
- **Separate authority:** agents.md states AGENTS.md “is now stewarded by the Agentic AI Foundation” under the Linux Foundation and links `agentsmd/agents.md`. agentsstandard.com instead names `nbiish/agents-standard` its spec repo and `nbiish/agentsstandard-dot-com` its site repo. The fetched sources do not establish that AAIF adopted nbiish's directory protocol. [AGENTS.md About](https://agents.md/); [Agents Standard footer](https://agentsstandard.com/).

- **N-AS rule formatting:** “Plain Markdown. No YAML frontmatter. No schema.” This statement describes rules, not the separate SKILL.md format. [Live File Format](https://agentsstandard.com/#spec); [pinned spec Format](https://raw.githubusercontent.com/nbiish/agents-standard/63e166a76acb61e6a197e2049ba1e87bea0ddf1a/llms.txt).
- **N-FORMAT AGENTS.md:** “No. AGENTS.md is just standard Markdown. Use any headings you like”; root AGENTS.md plus nested subproject files. No `.agents/AGENTS.md`, `llms.txt` PRD tier, MCP catalog, or providers tier is prescribed on the fetched agents.md page. [AGENTS.md usage/FAQ](https://agents.md/).
- **N-FORMAT SKILL.md:** “must contain YAML frontmatter followed by Markdown content”; `name` and `description` required. `name` must match the containing directory, be 1–64 characters with lowercase alphanumeric/hyphen conventions, no starting/ending or consecutive hyphens; `description` 1–1024 characters. Optional `license`, `compatibility`, `metadata`, experimental `allowed-tools`. A skill is a directory with required **exact `SKILL.md`**, optional `scripts/`, `references/`, `assets/`, and other files/directories. [Agent Skills specification](https://agentskills.io/specification).
- **N-AS versus N-FORMAT discrepancy:** nbiish v2 describes skills as “Markdown + optional YAML frontmatter,” but Agent Skills **requires** the frontmatter. Thus a frontmatter-free file accepted by nbiish's loader is not necessarily Agent Skills-conformant. [Pinned N-AS resource table](https://raw.githubusercontent.com/nbiish/agents-standard/63e166a76acb61e6a197e2049ba1e87bea0ddf1a/llms.txt); [Agent Skills format](https://agentskills.io/specification).
- **GUIDANCE installation paths:** Agent Skills says “the Agent Skills specification does not mandate where skill directories live (it only defines what goes inside them).” Its integration guide recommends considering both client-specific and `.agents/skills/` paths at project and home scopes, calls `.agents/skills/` “a widely-adopted convention,” and notes other scopes (admin, bundled, ancestors, XDG, configured paths) are implementation-dependent. This is explicit guidance/convention, not a filesystem-path requirement in the format spec. [Integration guide, Where to scan](https://agentskills.io/integrate-skills).
- **Live-site older MCP proposal:** “This standard proposes `~/.agents/mcp-settings.json` as a universal MCP config that agents can read”; its project examples use `.agents/mcp-settings.json`, and it says agent-specific configs extend the global set. **V2 reversal/clarification:** “The global catalog (`mcp-settings.json`) is never fed to agents directly” and “No tool reads `mcp-settings.json` as its MCP config.” Preserve both exact claims as different source/version statements. [Live site](https://agentsstandard.com/#mcp); [pinned v2 specification, MCP](https://raw.githubusercontent.com/nbiish/agents-standard/63e166a76acb61e6a197e2049ba1e87bea0ddf1a/llms.txt).
- **N-AS conformance levels in v2:** Minimal = single global or active rules file; Standard = full five-tier rules + global/project skills + project `.mcp.json`; Full adds skill override resolution, agent-specific MCP merge, and providers reference. These are **nbiish's definitions**, not independently verified client certifications. [Site-repo README protocol](https://github.com/nbiish/agentsstandard-dot-com#unified-loading-protocol); [pinned spec conformance table](https://raw.githubusercontent.com/nbiish/agents-standard/63e166a76acb61e6a197e2049ba1e87bea0ddf1a/llms.txt).

### Inferences

- “Native AGENTS.md” in a config map is insufficient evidence for support of `~/.agents/AGENTS.md`, `.agents/AGENTS.md`, PRD loading, cross-resource composition, or Full conformance. The map's own native entries include tool-specific homes such as `~/.deepagents/AGENTS.md` and `~/.config/zed/AGENTS.md`; official OpenCode rules use another home again. [Live registry](https://agentsstandard.com/agents.json); [OpenCode rules](https://opencode.ai/docs/rules/).
- Treat the v2 repository text as the latest fetched **repository specification**, and the v1.4 live JSON/site as the **deployed presentation**. Neither alone establishes client behavior; source and official docs must adjudicate each integration. [Live JSON](https://agentsstandard.com/agents.json); [pinned v2 JSON](https://raw.githubusercontent.com/nbiish/agentsstandard-dot-com/bb838b1853513bed0b6b5a897b407d3324737c00/agents.json).

### Gaps

- No independently verified ecosystem-wide adoption or certification of nbiish's complete protocol was found in the fetched sources. This is a bounded finding, not proof that no adopter exists.
- Repository heads were pinned for the nbiish sources; external product docs were fetched live. No archived snapshot or complete product release history was used to establish when each external-doc behavior first shipped.

## 2. How do global/home/project/nested/worktree discovery, priority, and inheritance actually work?

### Takeaway

There is no single `.agents/` scope/cascade algorithm shared by all examined clients. Even nbiish's deployed prose, v2 specification, and source loader differ: launch-directory ceiling versus marker-based root discovery; advertised depth behavior versus actual project loading; recursive-looking skill paths versus one-level scanning. Official integrations must be read per **resource type**, especially instructions versus skills. [Site](https://agentsstandard.com/#spec); [pinned loader](https://raw.githubusercontent.com/nbiish/agents-standard/63e166a76acb61e6a197e2049ba1e87bea0ddf1a/cli/lib/loader.js); [Codex instructions](https://developers.openai.com/codex/guides/agents-md); [OpenCode skills](https://opencode.ai/docs/skills/).

### Cited Findings

#### N-AS proposed discovery and inheritance

- **Live root scope:** “Agents detect the project root from the shell's initial `$PWD` at launch time”; `$AGENTS_ROOT` optionally overrides. “Agents must never traverse above this ceiling”; if the user changes directory outside it, “only `~/.agents/AGENTS.md` applies.” Thus live text's launch directory can be a subdirectory, rather than automatically the Git root. [Live Project Root Detection & Ceiling](https://agentsstandard.com/#spec); [live JSON root detection](https://agentsstandard.com/agents.json).
- **V2 root scope changes:** “walking up from the shell's initial `$PWD` looking for `.git`, `.agents`, or `llms.txt`”; priority `AGENTS_ROOT` then walk-up, home is the ceiling. But the v2 **site JSON still describes root as launch-directory inheritance**, so v2 artifacts themselves disagree. [Pinned spec root detection](https://raw.githubusercontent.com/nbiish/agents-standard/63e166a76acb61e6a197e2049ba1e87bea0ddf1a/llms.txt); [pinned site JSON](https://raw.githubusercontent.com/nbiish/agentsstandard-dot-com/bb838b1853513bed0b6b5a897b407d3324737c00/agents.json).
- **Rules order:** `~/.agents/AGENTS.md` → root `llms.txt` → root `.agents/AGENTS.md` → root `AGENTS.md` → applicable folder `AGENTS.md`. “Each tier's file is concatenated into the agent's context — not replaced.” V2 states “No rule is ever removed,” later rules override by position/specificity; precedence folder > active > base > global. This is prompt composition and a proposed conflict convention, not a parser mechanically deleting overridden sentences. [Site loading/adoption](https://agentsstandard.com/#spec); [pinned v2 inheritance](https://raw.githubusercontent.com/nbiish/agents-standard/63e166a76acb61e6a197e2049ba1e87bea0ddf1a/llms.txt).
- **Global safety tension:** v2 states “Global rules are immutable base. Project/folder extend but cannot weaken global safety,” while also declaring most-specific-wins for rules generally. No formal rule syntax or safety-classification algorithm is specified in the fetched format text. [Pinned v2 security invariants and inheritance](https://raw.githubusercontent.com/nbiish/agents-standard/63e166a76acb61e6a197e2049ba1e87bea0ddf1a/llms.txt).
- **Intermediate folder ambiguity:** live resolution list and v2 numbered list mention `{cwd}/AGENTS.md`; live Discovery/Adopt says walk from cwd upward collecting files to the project ceiling; v2 pseudocode says load each directory between root and cwd. Thus the broader texts support ancestors within the boundary, but the short numbered lists omit the intermediates. [Site Discovery/Adopt](https://agentsstandard.com/#adopt); [v2 pseudocode](https://raw.githubusercontent.com/nbiish/agents-standard/63e166a76acb61e6a197e2049ba1e87bea0ddf1a/llms.txt).
- **Advertised `AGENTS_DEPTH`:** 1 global only; 2 global + project base + PRD (live HTML); 3 additionally root active, default; 4+ additionally cwd folder. Live JSON omits PRD from its depth values and says cwd is “always read,” conflicting with default 3. `AGENTS_PATH` overrides global rules path; `AGENTS_ROOT` overrides root. [Live HTML depth](https://agentsstandard.com/#spec); [live JSON env_vars/traversal](https://agentsstandard.com/agents.json).
- **Skills N-AS v2:** “Keyed by directory basename”; project same-name skill “completely replaces” global, **no concatenation**. “Skills exist at global and project scopes only — no folder-level skills.” [Pinned v2 inheritance](https://raw.githubusercontent.com/nbiish/agents-standard/63e166a76acb61e6a197e2049ba1e87bea0ddf1a/llms.txt).
- **Skills GUIDANCE:** recommends deterministic collision policy; says project skills override user skills, and either first-found or last-found acceptable within a scope. This is an integration guide claim, not universally true product behavior: current Codex docs expressly allow duplicates. [Skills guide Handling name collisions](https://agentskills.io/integrate-skills); [Codex local skills](https://developers.openai.com/codex/skills.md).
- **MCP N-AS v2:** catalog is a definition store for `mcp pull`, project `.mcp.json` is runtime; agent-specific configuration extends it and wins same-server-name collisions; `disabled: true` excluded. **Providers N-AS:** home `providers.txt` only, no project/nested cascade; agent provider config overrides reference. [Pinned v2 inheritance/matrix](https://raw.githubusercontent.com/nbiish/agents-standard/63e166a76acb61e6a197e2049ba1e87bea0ddf1a/llms.txt).

#### IMPL: exact nbiish CLI loader behavior, pinned 2026-05-31

- `detectProjectRoot()` first honors existing `AGENTS_ROOT`, otherwise walks upward from `--project`/`process.cwd()` to the **first** directory with any of `.git`, `.agents`, `llms.txt`; it checks marker existence, not `.git` directory type. Stops before home/filesystem root. It does **not** retain an original shell-launch `$PWD`. An inner `.agents` or `llms.txt` therefore establishes an earlier root than an outer `.git`. [Loader, detectProjectRoot](https://raw.githubusercontent.com/nbiish/agents-standard/63e166a76acb61e6a197e2049ba1e87bea0ddf1a/cli/lib/loader.js).
- `load()` always calls `loadGlobalScope`, then calls `loadProjectScope` whenever a root exists, **regardless of depth 1/2/3**. All project PRD/base/active rules, root skills, and root MCP can therefore load even at depth 1. Only folder rules are guarded by `agentsDepth >= 4`. Depth parsed/clamped 1–10; default 3. This contradicts advertised “1 = global only,” “2 = base only” tier gating. [Loader, resolveEnv/load](https://raw.githubusercontent.com/nbiish/agents-standard/63e166a76acb61e6a197e2049ba1e87bea0ddf1a/cli/lib/loader.js); [constants](https://raw.githubusercontent.com/nbiish/agents-standard/63e166a76acb61e6a197e2049ba1e87bea0ddf1a/cli/lib/constants.js); [live advertised depth](https://agentsstandard.com/#spec).
- Folder loop walks **root downward toward cwd**, checks `AGENTS.md` at each path segment, and requires `4 + i <= depth`. Example root `/repo`, cwd `/repo/src/api`: depth 4 reads `/repo/src/AGENTS.md`, **not** `/repo/src/api/AGENTS.md`; depth 5 can read both. Comments claiming depth 4 is “cwd-level folder” disagree with the loop for multi-level cwd. Empty relative path or relative path starting `..` skips folders. No sibling directories scanned. [Loader, loadFolderScope](https://raw.githubusercontent.com/nbiish/agents-standard/63e166a76acb61e6a197e2049ba1e87bea0ddf1a/cli/lib/loader.js).
- Outside a configured root, folder loading is skipped but project scope **still loads** whenever root detection returned a root. Thus `AGENTS_ROOT=/repo` with cwd outside `/repo` does not implement the prose's global-only exit behavior; without an explicit root each call redetects from current cwd. [Loader, load/loadFolderScope](https://raw.githubusercontent.com/nbiish/agents-standard/63e166a76acb61e6a197e2049ba1e87bea0ddf1a/cli/lib/loader.js); [live root ceiling](https://agentsstandard.com/#spec).
- `findSkills()` performs a single `readdirSync` and tests each immediate child directory/symlink for `SKILL.md`; **no recursive `**` glob**. Skill identity is directory name, no YAML parsing or format validation. Global then root-project entries overwrite the name map; nested `.agents/skills` directories along root→cwd are not scanned. Project replacement is real map replacement, not instruction inheritance. [Helpers, findSkills](https://raw.githubusercontent.com/nbiish/agents-standard/63e166a76acb61e6a197e2049ba1e87bea0ddf1a/cli/lib/fs-helpers.js); [loader global/project skills](https://raw.githubusercontent.com/nbiish/agents-standard/63e166a76acb61e6a197e2049ba1e87bea0ddf1a/cli/lib/loader.js).
- Rules are concatenated with HTML scope/source comments. There is **no semantic conflict resolver**, global-safety weakening check, or enforced immutable instruction layer in this loader. Root active AGENTS.md symlink resolving exactly to root `.agents/AGENTS.md` is skipped to avoid duplication. Other rule links are read through ordinary filesystem APIs. [Loader, loadProjectScope/composeRuntimeState](https://raw.githubusercontent.com/nbiish/agents-standard/63e166a76acb61e6a197e2049ba1e87bea0ddf1a/cli/lib/loader.js).
- MCP runtime includes only root `.mcp.json`'s `mcpServers`, excluding `disabled: true`; global catalog contributes **path metadata only**. Agent-specific phase says “no additional loading happens here”: it records selected filenames/symlink targets diagnostically. Thus the loader itself **does not implement the proposed agent-specific MCP merge**. Provider text is read, but composed output returns only provider source/loaded metadata; skill output similarly exposes name/scope/path rather than loaded bodies. [Loader, global/project/bridge/composition](https://raw.githubusercontent.com/nbiish/agents-standard/63e166a76acb61e6a197e2049ba1e87bea0ddf1a/cli/lib/loader.js).
- `readFile()` catches read errors and returns null; it does not report them to loader metadata. The fetched helpers do not implement the v2 prose's seen-path-set cycle diagnostics. Symlink resolution can reach external targets because ordinary reads have no realpath containment check. These are source observations, not tested exploits. [Helpers, readFile/findSkills](https://raw.githubusercontent.com/nbiish/agents-standard/63e166a76acb61e6a197e2049ba1e87bea0ddf1a/cli/lib/fs-helpers.js); [v2 Edge Cases](https://raw.githubusercontent.com/nbiish/agents-standard/63e166a76acb61e6a197e2049ba1e87bea0ddf1a/llms.txt).

- **Codex instructions distinction:** official discovery does not list home `.agents/AGENTS.md`, root `.agents/AGENTS.md`, or PRD `llms.txt` as automatic instruction tiers. Its documented global guidance is `~/.codex/AGENTS.md` / override, not the Agents Standard map's `~/.codex/instructions.md`. This disproves treating the map as exact current instruction-discovery documentation; it does not prove `instructions.md` could never be read through some other mechanism. [Codex guide](https://developers.openai.com/codex/guides/agents-md); [Agents Standard map](https://agentsstandard.com/agents.json).
- **Codex arbitrary guide names require configuration:** default names plus `project_doc_fallback_filenames`; guide explicitly says “Filenames not on this list are ignored for instruction discovery.” Example `TEAM_GUIDE.md` is a configured fallback, not a universally auto-loaded guides directory. [Codex fallback section](https://developers.openai.com/codex/guides/agents-md).
- **OpenCode supports agent-compatible skill paths, not the proposed global rule path by that fact alone.** Rules docs name `~/.config/opencode/AGENTS.md`, while skills docs expressly name `~/.agents/skills`. Docs say custom `instructions` globs/URLs combine with AGENTS.md and that references in AGENTS.md are **not automatically parsed**. [OpenCode rules](https://opencode.ai/docs/rules/); [OpenCode skills](https://opencode.ai/docs/skills/).
- **Claude native AGENTS.md is now documented**, contrary to the older nbiish registry's symlink-only account: requires v2.1.277+, default uses AGENTS only when no CLAUDE.md, `.claude/CLAUDE.md`, or CLAUDE.local.md exists on cwd's ancestor path. User/managed CLAUDE files do not suppress it. Native fallback reads `AGENTS.md` and `.claude/AGENTS.md` along ancestors; descendants on Read when they have no own CLAUDE files. Exact exclusion: “Not read: `AGENTS.local.md`, `AGENTS.override.md`, or anything under a `.agents/` directory.” This exclusion is in the **instruction loading section**, not a universal claim about skills. [Claude memory AGENTS.md](https://code.claude.com/docs/en/memory#agents-md); [nbiish registry](https://agentsstandard.com/agents.json).
- **Claude instruction conflicts:** “All discovered files are concatenated into context rather than overriding each other”; elsewhere “Neither set overrides the other” and a user/project conflict may follow either. This is materially weaker than N-AS's claimed deterministic most-specific-wins. Default Claude ancestor traversal also differs from the proposed project-root ceiling. [Claude memory loading/user-level rules](https://code.claude.com/docs/en/memory).
- **Worktree specifics verified:** OpenCode skills explicitly stop at “git worktree”; nbiish root detection treats `.git` **existence** as a marker (therefore a worktree `.git` file qualifies, by source inference), with no special shared-main-worktree scope. Claude docs say ignored `CLAUDE.local.md` exists only in the worktree where created; home-file imports can share personal instructions. Claude auto memory, a **separate resource**, is shared among worktrees/subdirectories of the same repository. [OpenCode skills](https://opencode.ai/docs/skills/); [nbiish loader](https://raw.githubusercontent.com/nbiish/agents-standard/63e166a76acb61e6a197e2049ba1e87bea0ddf1a/cli/lib/loader.js); [Claude imports/storage](https://code.claude.com/docs/en/memory).
- **Adoption claims not independently confirmed here:** nbiish v2 calls Pi, CodeWhale, Kilo, OpenCode, Deep Agents, and Zed “Native AGENTS.md agents (read ~/.agents/AGENTS.md directly, no symlink needed).” OpenCode official rules document another global location. Pi's registry `docs_url` points back to nbiish's own repo, not Pi source. CodeWhale's linked repository redirected to `codewhale-hq/Codewhale`; fetched README did not specify `.agents/AGENTS.md` discovery. Therefore the generic list cannot be used as verified adoption of the full/global protocol. [N-AS native list](https://raw.githubusercontent.com/nbiish/agents-standard/63e166a76acb61e6a197e2049ba1e87bea0ddf1a/llms.txt); [registry](https://agentsstandard.com/agents.json); [OpenCode official rules](https://opencode.ai/docs/rules/); [CodeWhale linked repository](https://github.com/Hmbown/CodeWhale).

### Inferences

- A portable root `AGENTS.md` plus exact-name SKILL.md capability directories has stronger direct interoperability evidence than mandatory root `.agents/AGENTS.md`, automatic PRD context, shared MCP catalog runtime, or provider auto-configuration. Actual adopted `.agents/skills` scopes can include **nested** folders although N-AS v2 restricts skills to global/root-project. [AGENTS.md](https://agents.md/); [Codex skills](https://developers.openai.com/codex/skills.md); [OpenCode skills](https://opencode.ai/docs/skills/); [N-AS spec](https://raw.githubusercontent.com/nbiish/agents-standard/63e166a76acb61e6a197e2049ba1e87bea0ddf1a/llms.txt).
- There is no basis in these sources to claim that configuration in a main checkout's `.agents/` automatically applies to a distinct linked worktree. Ordinary checked-in files may travel with checkout contents, and home resources may be shared, but those are different mechanisms from a normative cross-worktree cascade. [N-AS marker loader](https://raw.githubusercontent.com/nbiish/agents-standard/63e166a76acb61e6a197e2049ba1e87bea0ddf1a/cli/lib/loader.js); [OpenCode git-worktree boundary](https://opencode.ai/docs/skills/); [Claude local-worktree distinction](https://code.claude.com/docs/en/memory).

### Gaps

- Exact OpenCode same-name skill collision winner is not established by its fetched official docs; no OpenCode source audit or runtime check was performed. Do not import N-AS's precedence rule to fill this gap.
- Git submodules, nested Git repositories, multi-root IDE workspaces, Windows home expansion/case semantics, and main-worktree/common-Git-directory sharing are not comprehensively specified in the fetched N-AS material.
- No runtime clients or CLI were installed/executed. IMPL findings are static source verification at the pinned commit; DOC-IMPL findings are official-doc verification, not execution traces.

## 3. What applies to instructions, skills, research, guides, and configuration?

### Takeaway

The fetched standards define **specific entrypoints**, not automatic loading of arbitrary files placed in `.agents/`. Research and guides can be skill resources or explicit instruction references, but no fetched normative text establishes `.agents/research/`, `.agents/guides/`, `RESEARCH.md`, or `GUIDE.md` as universally discovered/cascading resource types. Instruction concatenation, skill activation, reference loading, and executable configuration remain distinct operations. [N-AS resource matrix](https://raw.githubusercontent.com/nbiish/agents-standard/63e166a76acb61e6a197e2049ba1e87bea0ddf1a/llms.txt); [Agent Skills specification](https://agentskills.io/specification); [integration guide](https://agentskills.io/integrate-skills).

### Cited Findings

- **Behavior instructions:** N-AS defines AGENTS.md as “how the agent should behave,” separates root `llms.txt` what/why from how, and concatenates recognized rules files. agents.md itself allows project overview, commands, style, tests, security and other useful context in root/nested AGENTS.md; it **does not require PRD/context to be separated out**. [N-AS separation](https://agentsstandard.com/#spec); [AGENTS.md usage](https://agents.md/).
- **Skills/capabilities:** N-AS says SKILL.md is “what the agent can do”; Agent Skills defines progressive disclosure: startup metadata; full instructions on activation; scripts/references/assets only as needed. Thus an instruction-like paragraph inside an unactivated skill is not necessarily already active merely because it resides under `.agents/skills`. [Site relationship](https://agentsstandard.com/#adopt); [Skills specification progressive disclosure](https://agentskills.io/specification); [OpenCode on-demand tool](https://opencode.ai/docs/skills/).
- **Research and guides inside a skill are supported as content:** format permits “any files and directories beyond the required `SKILL.md`”; `references/` is recommended for additional documentation; examples `REFERENCE.md`, `FORMS.md`, domain-specific `.md`. Relative paths resolve from skill root; resources load “only when required.” No format rule says every guide/research file should itself become a SKILL.md. [Agent Skills optional directories/file references](https://agentskills.io/specification).
- **Concrete repository example, not a new standard entrypoint:** website repo's 2026-05-31 commit added `.agents/skills/advisory-council/RESEARCH.md` (219 lines) alongside `SKILL.md`. This proves the repository contains research as a **skill companion file**, not an independently discovered `RESEARCH.md` resource type. The file's title is “Research: Expanding `advisory-council` Beyond Finance While Preserving Personas.” [Pinned commit file entry](https://github.com/nbiish/agentsstandard-dot-com/commit/bb838b1853513bed0b6b5a897b407d3324737c00); [pinned research file URL](https://github.com/nbiish/agentsstandard-dot-com/blob/bb838b1853513bed0b6b5a897b407d3324737c00/.agents/skills/advisory-council/RESEARCH.md).
- **Discovery targets SKILL.md, not all Markdown:** Skills integration guide says look for subdirectories with “a file named exactly `SKILL.md`”; a `README.md` in the skills directory is shown as “ignored.” It says a dedicated activation tool may enumerate bundled resources but “should not eagerly read them.” [Integration guide, What to scan for/Listing bundled resources](https://agentskills.io/integrate-skills).
- **Generic external instructions are tool-specific:** OpenCode `instructions` config supports paths/globs/remote URLs, combined with AGENTS.md. Its docs: “opencode doesn’t automatically parse file references in `AGENTS.md`.” Claude's AGENTS/CLAUDE machinery supports `@path` imports, expanded at launch, with relative paths based on the containing file and recursive imports up to four hops. Codex can recognize alternate guide filenames through configured fallbacks. None of these mechanisms establishes a universal `.agents/guides` cascade. [OpenCode rules](https://opencode.ai/docs/rules/); [Claude imports](https://code.claude.com/docs/en/memory#import-additional-files); [Codex fallbacks](https://developers.openai.com/codex/guides/agents-md).
- **MCP and provider configuration:** N-AS v2's resource table specifies JSON MCP `mcpServers` and TSV provider reference. Its provider design says “a base standard that agents CAN read, not a replacement for agent-specific provider configuration.” Its own cross-tool map lists different live config names/formats (Codex TOML, OpenCode JSONC, Gemini JSON settings, Goose YAML). This is positive evidence of integration diversity rather than automatic universal consumption. [Pinned v2 providers/MCP maps](https://raw.githubusercontent.com/nbiish/agents-standard/63e166a76acb61e6a197e2049ba1e87bea0ddf1a/llms.txt); [live config maps](https://agentsstandard.com/#mcp).
- **Config symlinks are not format adapters:** live JSON lists Aider `.aider.conf.yml` and Continue `config.json` as symlink candidates while admitting YAML/JSON rather than Markdown; pinned CLI registry marks both “manual setup.” The independent agents.md page instead tells users to put **`read: AGENTS.md`** in Aider YAML. A symlink alone does not make arbitrary Markdown valid YAML/JSON configuration. This conclusion is a file-format inference backed by the explicitly different formats and manual/configured approaches. [Live registry](https://agentsstandard.com/agents.json); [pinned CLI constants](https://raw.githubusercontent.com/nbiish/agents-standard/63e166a76acb61e6a197e2049ba1e87bea0ddf1a/cli/lib/constants.js); [AGENTS.md Aider FAQ](https://agents.md/).
- **Instructions are not enforced client configuration:** Claude official docs say “Claude treats them as context, not enforced configuration,” and describe settings as the enforcement layer. N-AS's loader likewise only concatenates text, rather than interpreting AGENTS.md as machine-enforced policies. [Claude memory overview/managed policies](https://code.claude.com/docs/en/memory); [nbiish composeRuntimeState](https://raw.githubusercontent.com/nbiish/agents-standard/63e166a76acb61e6a197e2049ba1e87bea0ddf1a/cli/lib/loader.js).

### Inferences

- For universal agent-content composition, distinguish: (1) format-valid **entrypoint**, (2) discovery **location**, (3) scope and collision **selection**, (4) eager versus on-demand **loading**, and (5) content's instruction/reference/configuration **role**. None of the fetched standards supplies one inheritance rule for arbitrary `.agents/**` content. [N-AS four-resource inheritance matrix](https://raw.githubusercontent.com/nbiish/agents-standard/63e166a76acb61e6a197e2049ba1e87bea0ddf1a/llms.txt); [Skills guide lifecycle](https://agentskills.io/integrate-skills).
- Research/guide names can be local organizational conventions; interoperability requires a recognized root/nested instruction entrypoint, an activated skill/reference, or a client-configured loader. Claiming universal auto-loading from the directory name alone would exceed the verified evidence. [Skills optional resources](https://agentskills.io/specification); [OpenCode configured instructions](https://opencode.ai/docs/rules/); [Codex configured fallback names](https://developers.openai.com/codex/guides/agents-md).

### Gaps

- No normative naming, schema, discovery order, inheritance, or worktree-sharing rules for standalone research/guides directories were found in the fetched primary materials. This does not prohibit those directories; it means their automatic behavior is unestablished.
- No search tool, archive service, browser automation, or subagents were used. Research followed the site's source/specification links and primary format/product documentation; it did not exhaustively audit all roughly 30 tools in the site's registry.
- The live site, live JSON, repository README, v2 `llms.txt`, and source contain unresolved differences. These notes preserve those differences rather than offering a falsely exact unified algorithm. External pages lacking revision dates remain live retrieval evidence as of 2026-10-09.
